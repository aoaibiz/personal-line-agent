# 初回導入と運用

初回のインストール・設定・本人認証では、利用者本人によるターミナル使用を許容します。導入後の通常操作・更新・再接続・復旧の内部コマンドは、権限のあるエージェントや実行基盤が担当し、人間にPC操作を要求しません。後者の全経路の検証は残っています。初回導入専用GUIは完成の必須条件ではありません。

## 前提

- macOS、Python 3.11以上（実測3.12）、Git、uv、OSキーチェーンが使用できること。
- 本人所有のLINEアカウントと、そのスマホで接続を確認できること。
- 対応するローカルstdio MCPクライアント。ホストの認証・権限設定に従うこと。

## インストール・接続

取得したリポジトリで、利用者本人または担当エージェントが以下を実行します。

```sh
uv sync --frozen
.venv/bin/line-agent init
```

データの既定保存先は`~/.local/share/personal-line-agent/personal/`です。複数アカウントには`--account <別名>`を使い、MCP側にも同じ名前を設定します。

初回の接続は`.venv/bin/line-agent login`で開始します。ターミナルに表示されるQRを本人のスマホで読み取り、必要なPIN確認を本人が行います。QR/PINをAIのチャット・共有ログへ送らないでください。認証済み接続は保存して再利用します。導入後に再認証が必要になった際、人間にPC操作を要求せず完了する経路は未完成です。

認証後は[運用手順の初回登録](OPERATIONS.md#初回登録初回だけ人間のターミナル使用可)に従い、非editableの固定入口をMCPホストへ一度登録します。バックエンドを直接登録する旧方式では、更新時にホストの再読込みが必要になるため、新規導入には使いません。

ホストの設定形式はクライアントによって異なります。秘密をこの設定例へ埋め込む必要はありません。新しい本人認証時に全対象・実装済み8操作の既定権限を設定します。既存制限・失効は保持します。

## 通常操作

1. `agent_status`で接続・受信・停止・結果不明を確認。
2. 読取ツールで対象を名前とIDにより確定。同名の公式アカウント等を混同しない。
3. 所有者の指示を受け、`operation_run`に固定した依頼UUID・操作種別・内容を渡す。
4. `operation_status`と読取ツールで結果を照合。同じ依頼のUUIDを保持する。

一時停止・失効・範囲外・会話変更・結果不明を理由なしに解除しない。`sending`/`unknown`を新しい依頼として再送しない。全対象権限だけを根拠に未指示の一斉送信を行わない。

## 所有者設定・新着処理

`configure-operations`は信頼された所有者側の導入担当用で、MCPへ公開されません。所有者の指示で制限を変更するときだけ使います。人間の操作や承認を偽る引数ではありません。

`worker --events`は新着受信プロセスです。MCP起動だけで24時間受信するわけではありません。Macの停止・接続失効・受信位置不整合は可視化して扱います。パッケージのインストールだけでは起動項目を追加しません。導入担当は[運用手順](OPERATIONS.md#mac受信サービス所有者エージェント用)の専用受信サービス登録まで行い、実受信を確認してください。

返信支援は任意の`assist-config`/`assist`経路です。対応するローカル正規化DBと分類データ、外部送信への所有者同意、利用可能なCodex CLIが必要です。固定モデル`gpt-6.1-sol`やCLI引数が使えない環境では診断付きで停止します。モデルの利用権や料金を無料と保証しません。任意のLINEバックアップを直接読み込む機能ではありません。

## 更新と復旧

導入担当が前のコミット・依存ロックを記録し、アカウント保存先と鍵を保全してから`uv sync --frozen`で更新します。固定入口を初回登録した環境では、[運用手順](OPERATIONS.md)の版切替を使います。旧来の直接接続の再読込みはホスト依存であるため、新しい配布では固定入口を使います。認証・履歴・受信位置を削除して復旧を装わないでください。

失敗時は停止し、操作状態を確認してコードとロックを前版へ戻します。送信済みや結果不明の操作は巻き戻したことにしません。人間がPCへ戻らず、エージェントや実行基盤から更新・復旧を完結できる全経路の実装・検証は残っています。
