# 受信画像取得（2026-10-29）

`runtime_call`で`received_images_get`を呼ぶ。引数は`chat`（通常グループID）と`message_ids`（1〜5件）。指定グループの直近100件でID・宛先・画像種別を照合し、既存接続で原本を取得する。メタデータや鍵は返さない。送信・既読・鍵登録RPCは禁止。

返却値は画像ごとの状態、保存絶対パス、サイズ、SHA-256。保存先はアカウント内received-images、0700/0600。Windowsでは共通のprivate_directory/private_openを通して所有者向けACLを設定し、reparse pointを拒否する（今回の受信画像機能はWindows実機未検証）。画像ファイル自体は平文であり、暗号化DBとは別です。本人の端末・接続先AI以外へ共有せず、Gitへ含めません。1画像32MiB、保存先全体256MiB・200ファイル上限。限界時は明示的に失敗し、自動削除しない。同じ画像の再取得も新しいファイルを保存するため不要な再取得を避ける。JPEG/PNG/GIF/WebPのヘッダー判定後、実際の表示・デコードは別途確認する。

対象グループの画像5件を正式MCP経由で取得し、5件とも実表示を確認。既存接続・受信状態は正常。初回の実取得後に、HTTPコード保持・リダイレクト拒否・ストリーム容量・復号失敗・RPC名前空間を検証する回帰テストを追加。独立レビューの中リスク2点（範囲・総容量）は制限を追加して対応した。

アルバム一覧・アルバム画像、古い履歴のページ巡回、個人トークはこの追加機能の対象外。全メディア対応とはしない。個人情報を含む実ID・画像は公開ソースに入れない。
