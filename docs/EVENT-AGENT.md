# グループ新着のイベント駆動AI処理（macOS）

この機能は、LINEの受信イベントを契機に**専用のAI処理を開始する機能**です。
今開いているCodex/ChatGPTのローカルチャットを即時起動する機能ではありません。
AI推論・LINE通信の時間がかかるため、返信時刻の即時性は保証しません。
Cloudや別チャットへの移行は不要です。従来の受信・画像取得・操作台帳は維持します。
Windowsのこの処理サービスは未対応です。従来のWindows受信機能には変更しません。

## 行うこと

- 所有者が明示的に設定した通常グループだけを対象にします。初期状態は無効です。
- SSE受信と同じトランザクションで、メッセージIDに結び付いた処理票を暗号化保存します。
- 別プロセスがmacOSのファイル変更イベントで起動し、対象グループの直近最大30発言と所有者の方針だけをAIに渡します。受信処理の中では推論しません。
- 既存Codexログインを利用し、AIのシェル・ツール・ファイル閲覧を無効にします。APIキーは要求しません。
- 返信不要、通常返信、サイト作業、所有者の判断が必要、を区別します。
- 通常返信は別途 `allow_replies` を許可した場合だけ、正式MCPの `operation_run` を使います。既存の分類・下書き作成の同意を自動送信に流用しません。
- 写真・動画を実際に見る機能や、サイトを編集・公開するツールはこのAIにはありません。サイト作業は担当エージェントへ引き継ぎます。

## 導入・設定・更新は所有者のエージェントが行う

人間にコマンドの転記や実行を頼みません。所有者のエージェントが `docs/OPERATIONS.md` に従い、検品済み固定ソースを別リリースへstageし、既存アカウント接続を検証してactivateします。アカウントDB・鍵・受信位置・送信台帳は戻しません。

管理エージェントは、候補リリースのPythonから `python -I -B -m line_agent.event_agent --home MANAGED_HOME --root ACCOUNT_ROOT --account ACCOUNT configure` を実行し、標準入力に以下の形を渡します（値は本人が承認した対象・方針）。

```json
{"chat":"本人が選んだ通常グループID","enabled":true,"allow_replies":false,"max_daily":20,"instructions":"本人が承認した業務範囲・既知の事実・文体"}
```

- `instructions` は対象グループへ公開してよい方針・事実だけにします。秘密、社内限定情報、他トークの情報は入れません。モデルに渡す内容の機密性を文字列検査だけで保証することはできません。
- `allow_replies` は初期値false。trueへの変更には所有者の実際の許可が必要です。
- 設定前の履歴を自動処理しません。設定後の実新着のみが対象です。
- 1グループ1日最大50回、初期値20回の推論上限。CLIの利用枠や接続状況によって失敗する場合があります。
- 同じエージェントが `install` → `start` を実行すると、アカウントごとの専用LaunchAgentを登録・起動します。Mac起動・OSログイン前や電源OFF中には動きません。
- 設定はMCPやLINE本文から追加・拡張できません。ローカル所有者の管理操作に限ります。
- 秘密・会話本文・対象者の実IDをGitHubの設定例や試験記録へ入れません。

## 状態と引継ぎ

正式MCP `event_agent_status(chat)` （固定入口の一覧が古い場合は `runtime_call`）から、処理ID・状態・引継ぎを確認できます。状態の `site_task` は作業受付であり、実装・公開完了ではありません。`owner_required` は自動送信していないか結果不明です。

既存の定期監視を併用する担当は、必ずこの状態と最新LINE履歴を確認します。`sent` または処理中の同一メッセージへ重複返信しません。サイト作業は元のメッセージIDを一意キーにして引き継ぎます。

## 停止・復旧

所有者のエージェントが `stop` を実行すると、当アカウントのイベントAIポリシーを無効にし専用LaunchAgentを停止します。従来のLINE受信と手動MCP操作は継続できます。再ログインでサービスが起動しても、無効ポリシーが自動で有効にはなりません。再開は対象と方針を確認して再configureします。

- 推論中に本人が返信、会話更新、設定変更、全体pauseが発生した場合、送信前の再取得で古い結果を捨てます。
- 処理・送信中に終了した票は、再起動時に自動再送しません。所有者エージェントが保存済みrequest UUIDの `operation_status` と実履歴を確認します。
- 一度送信が開始したものを停止操作で取り消すことはできません。
- `failure_stage` と閉じた `reason`、`next_check` を記録します。外部エラー全文やモデル入力は診断ログへ出しません。
- 旧コードへ戻す場合は先にこのサービスをstopし、既存のruntime rollbackを使用します。既存の5分監視は即時処理の実経路検証が済むまで止めません。

## 検証の区別

合成アカウントで、イベント→キュー→判断→送信コールバック、重複イベント、本人先返信、処理中の設定無効化、結果不明、履歴欠落、サイト作業引継ぎ、対象外グループ、ファイル変更イベントを確認します。合成試験を実LINE送受信の成功とは扱いません。

導入先では、実新着→AI処理→必要な通常返信の正式MCP実行→LINE履歴で読戻し、までの証拠を別に残します。未実施なら「実運用未確認」と報告します。顧客グループへ試験文は送りません。
